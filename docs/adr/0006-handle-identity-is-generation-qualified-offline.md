# Handle identity is generation-qualified offline, not allocated at capture

A `HandleId` is derived from the raw value the driver handed out (SplitMix64 of `raw ^ kind.salt()`), which is what lets two host threads agree on the identity of one allocation with no shared map, no counter and no lock on the record path (ADR-0004). It is stable but not injective over a run: a driver that frees an allocation and hands the same address back gives two unrelated objects one id, and a replay remapping by id alone would send the second object's work to the first. The obvious fix — a process-wide `raw -> id` table — reintroduces exactly the serialization point ADR-0004 exists to refuse. We instead apply the answer we already gave ordering: **record enough to recover identity offline rather than enforce it while recording.** Records already carry `Produced`/`Consumed`/`Destroyed` bindings with a thread, a per-thread sequence number and a monotonic stamp, so `gputrace_core::identity` walks those bindings and re-scopes each raw id into generation-qualified objects (`ObjectId { handle, generation }`).

The residual limitation is honest rather than hidden. Within one host thread the sequence numbers give a total order, so every lifetime boundary is provable and every call resolves. Across threads nothing is provable: `timestamp_ns` is read when a call *begins*, not when the driver answers, and a non-stream call earns no happens-before edge, so a free racing a reallocation on another thread can be stamped in the opposite order to the one the driver actually applied. A call that could belong to either lifetime therefore resolves to `Resolution::Ambiguous`, listing the candidates, and is reported through `HandleIdentities::ambiguities()`. A consumer must refuse such a call rather than pick one — a resolver that says "I cannot prove which object this is" is correct; one that guesses is not. Narrowing that gap means capture recording an end-of-call stamp as well as a begin-of-call one, or the happens-before graph growing to cover non-stream calls; neither is needed for the capture phase and both are left to whoever needs the precision.
