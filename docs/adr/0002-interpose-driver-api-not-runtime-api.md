# Interpose the Driver API, not the Runtime API

Most applications use the CUDA Runtime API (`libcudart.so`, `cuda*`), so the obvious choice would be to interpose there. We instead interpose the **Driver API** (`libcuda.so`, `cu*`). Rationale: the Runtime API ultimately lowers onto the Driver API, so a Runtime-API program still funnels its real work through `libcuda` and is captured anyway; the Driver API surface is smaller and churns far less across CUDA versions; and `libcuda.so` ships with the NVIDIA driver itself (no toolkit required on the target), whereas `libcudart` requires the toolkit. The cost: calls are observed at a lower semantic level than `cudaMalloc`-style names, which the deep handlers compensate for on the curated subset. Interposing the Runtime API (or both surfaces) remains possible as a later layer.
