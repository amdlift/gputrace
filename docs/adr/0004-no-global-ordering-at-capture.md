# No global ordering at capture; reconstruct happens-before offline

The intuitive way to order a multi-threaded trace is a single global, sequentially-consistent sequence counter stamped on every intercepted call. We rejected this: that counter is a shared serialization point on the capture hot path, and it would perturb the very parallelism the tool exists to study (a Heisenberg effect that undermines our core thesis for DARPA-SN-26-56). Instead each record carries a per-thread monotonic counter plus a high-resolution monotonic timestamp (`CLOCK_MONOTONIC_RAW`, vDSO-cheap), optionally with a *relaxed* global atomic tiebreaker; the cross-thread/stream **happens-before partial order is reconstructed offline** from recorded stream/event operations. We record enough to *recover* ordering rather than *enforcing* a total order at capture time. The trade-off is more analysis-time complexity in exchange for a trace that faithfully reflects concurrent behavior.
