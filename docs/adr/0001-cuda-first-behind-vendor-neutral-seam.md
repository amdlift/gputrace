# CUDA-first, behind a vendor-neutral seam

DARPA-SN-26-56 views solutions limited to a single vendor's make and model unfavorably, yet our only test hardware is NVIDIA and a credible prototype must go deep on one API. We decided to build CUDA as the first and only concrete `Backend`, but to define the trace representation and the capture/replay/mutate operations in a backend-agnostic `gputrace-core` crate behind a `Backend` trait. This keeps the "broadly applicable to GPUs/NPUs/TPUs" claim architecturally real (ROCm/oneAPI/NPU backends can be added without reworking the core) without spending prototype effort on hardware we cannot test. The alternative — committing fully to CUDA with no abstraction — was simpler but weaker against the evaluation criteria and expensive to retrofit later.
